# Website dependency qualification: source reachability and remaining decisions

Research snapshot: 2026-10-26. Starting point: integration `ea550fb5bc338d6c15ec5f596e6f3f8586bf489a`, fast-forwarded to website commit `fa558adb167c734026dd7d42a5ef74792cb39374` on the isolated research branch. This report is research, not a qualification receipt, legal opinion, exception, scanner suppression, or release authorization. Only this Markdown file is changed. Project code, locks, audit/license policy, publication settings, private repositories, and the predecessor repository were not changed or consulted.

## Findings that change the decision

1. **The 73 findings are reproducible as source-lock matches, not 73 demonstrated website vulnerabilities.** Querying OSV for the exact checked-in upstream package identities reproduced 51 Pagefind native, 19 Pagefind JS, two Astro compiler, and one Sätteri occurrences. There are 71 unique ecosystem/package/version/advisory rows, 67 advisory IDs, overlapping aliases, and repeated packages across source locks. The complete ledger below retains every occurrence. The separate website pnpm graph was reported clear in [the implementation validation](../validation-115.md); this research did not rerun the project's full scanner or application tests.
2. **npm Pagefind 1.5.2 runs an extended native CLI, with default `serve` support compiled in.** Its extra tokenizer dependencies are real build/binary qualification subjects. They are not browser dependencies. Under the recorded DE/EN command, the Chinese/Japanese/Thai segmentation branch and preview server are not selected. Rustls certificate/network advisories concern the upstream dictionary build path; Quinn is not selected by that release feature tree at all. These conclusions have explicit configuration and binary-provenance limits below.
3. **The browser WASM has its own small graph.** None of the 73 advisory matches occurs in `pagefind_web/Cargo.lock`. In particular, the native `zstd-sys` wasm32 advisory does not imply that Pagefind's browser WASM contains zstd. Conversely, `pagefind_microjson@0.1.4` really is a direct, used WASM dependency and a GPL distribution issue; it cannot be dismissed as a development package.
4. **The source-lock critical `tar@7.5.13` finding is AVA test-tooling ancestry, not a module bundled into the search client.** It still matters to the upstream environment that installed/executed that tooling. The actual JS build uses esbuild, but not its Windows development server. The application's pnpm build consumes already-bundled Pagefind assets rather than installing that upstream npm lock.
5. **Sätteri's `bincode@2.0.1` is explicitly a Rust dev-dependency used in serialization tests.** It is absent from the release N-API dependency tree. In this website, there are no Markdown/MDX inputs and Astro loads the Sätteri binary lazily when the Markdown processor runs. The earlier broad statement that Sätteri necessarily executes for this site is not established by these sources.
6. **The two Lightning CSS prereleases remain a concrete maturity-rule issue.** `astro_napi → astro_codegen → lightningcss@1.0.0-alpha.72 → lightningcss-derive@1.0.0-alpha.43` is a selected compiler build path, not an unrelated workspace test. No stable version of either crate is published. Compiler 0.5.1, the other compatible existing patch, has the same Lightning CSS declaration; Astro 7.4.0/7.4.1/7.4.2 all require compiler `^0.5.1`. There is no evidenced compatible stable patch substitution that removes these prereleases. `get-tsconfig` approval does not cover them.
7. **Several advisory fixes fit existing Rust semver constraints, but cannot be delivered by an npm override.** They need an upstream rebuilt binary or a separately qualified source rebuild. No newer published Pagefind 1.5.x, Astro 7.4.x, compiler 0.5.x, or Sätteri 0.10.x patch was available in the queried registry snapshot. zstd and h2 require parent dependency changes or feature removal, rather than a same-range patch. Unmaintained notices have no patched version.
8. **The current evidence is insufficient for dependency/publication approval.** Precise remaining choices are a bounded compiler-prerelease decision, a Pagefind binary/remediation route, and legal approval of an actual GPL/WASM source-and-notice package. There is no basis here for a blanket waiver. ADR-0015's critical-finding rule, security qualification, and ADR-0020's publication gates remain in force.

## What ships, what executes, and what is merely available

### Product path

[The website build script](../../apps/website/scripts/build.ts) executes `astro build`, then Pagefind twice with `--force-language de/en`, `--glob docs/{language}/**/*.html`, and separate local output directories. It does not invoke Pagefind's `--serve`, AVA, the upstream JS build, or a Rust compiler. Astro is configured for static output. [The browser search adapter](../../apps/website/src/search.ts) imports the local per-language `pagefind.js`, calls `search()`, and loads result data; it does not import Pagefind's UI or highlighting packages. The hosting layer nevertheless serves every inventoried asset, so copied-but-unused UI/highlight assets still count as distributed files.

The release workflows assemble prebuilt artifacts and publish packages; they are not per-binary dependency SBOMs. Pagefind rewrites placeholder versions, uses `npm i` rather than immutable `npm ci`, invokes Cargo builds without `--locked`, and builds WASM using nightly/build-std. The compiler release collects artifacts from its CI workflow. Neither an attestation of publishing nor an exact tag lock proves the final resolved versions/features, vendored inputs, C library configuration or eliminated code for every released platform. Obtain build-run evidence/attested component SBOMs, or reproduce a controlled build with recorded toolchain and dependency resolution, before claiming that level of provenance. No nightly toolchain or unapproved compiler prerelease was executed here.

Additional inventory gap: Pagefind's [vendored `gz.js`][P-gzip] carries fflate's MIT header but no independently pinned fflate version in the upstream JS manifest. File SHA-256 at this source commit is `7450eb4426973ca026c8d18cfec66f09317fb249f8f7f3ca1d2153b6b71e0158`. Retain this vendored source identity and notice; do not silently label the full browser client as only the npm production dependency `mark.js`. Likewise, the script's default MIT assignment for all local/git workspace packages is not an individual source-license clearance.

## Advisory applicability, separate from package matching

The ledger gives exact affected ranges and fixes for every reported match. The following distinguishes the meaningful execution conditions. “Not selected” is a source/feature conclusion at the recorded inputs, never a blanket assertion about arbitrary binaries or future configurations.

### Native Pagefind

- **Actix HTTP 3.12.0**, [GHSA-xhj4-vrgc-hr34](https://github.com/actix/actix-web/security/advisories/GHSA-xhj4-vrgc-hr34): HTTP/1.1 CL.TE request smuggling requires an Actix server behind a disagreeing intermediary with reused upstream connections. Maintainer prose says versions through 3.12.0, fixed 3.12.1, while its machine-readable affected field says `<3.12.0`; the discovery record includes 3.12.0. Retain the discrepancy conservatively. The default feature is compiled in; the recorded indexing invocation does not enter `serve_dir`. The actual website server is Node/Hono, not Actix. An uncontrolled `PAGEFIND_SERVE`/config change would change the assessment.
- **h2 0.3.27**, RUSTSEC-2026-0258: empty DATA frame queue growth, affected `<0.4.16` in RustSec, patched 0.4.16. It is through Actix's optional HTTP/2 support. No HTTP server is started by the normal command; no intended website request reaches h2. Updating to h2 0.4.16 is not compatible with actix-http 3.12.0's `h2 = "0.3.27"` constraint. Removing unused serve support avoids this parent/API change in a controlled native build.
- **Quinn 0.11.14**, memory exhaustion/panics in RUSTSEC-2026-0185/0338/0339/0340/0342 (fixes 0.11.15/17/18): resolved lock entries, **not selected** in normal+build release trees. Reqwest enables Rustls roots, not `http3`. The HIGH remote reassembly DoS therefore has no evidenced compiled or executed path in this source configuration. Keep all six raw alias rows in the ledger. No browser QUIC conclusion follows from a Cargo lock entry.
- **Rustls 0.23.37 / rustls-webpki 0.103.10 / webpki-roots 1.0.6**: selected only for the Lindera dictionary host build, not the normal executable dependency tree. This is an actual upstream **network-consuming build path**, not fictitious test-only ancestry. High CRL panic (webpki `<0.103.13`) needs malformed CRL parsing; the cited build source does not demonstrate use of a CRL verifier. Name-constraint issues require qualifying certificate conditions, not arbitrary unauthenticated certificate acceptance. Root distrust is relevant to a build fetching HTTPS dictionaries, but no compromised dictionary download is demonstrated. Rustls Brotli decompression needs its nondefault `brotli` feature (absent here), secret logging needs a custom session store's `Debug` output, and key-exchange downgrade needs retry state. The blanket TLS-version findings do not prove all those conditions. Stable fixes exist; correct host-build provisioning/provenance remains necessary.
- **tar crate 0.4.45**, [GHSA-3pv8-6f4r-ffg2](https://github.com/composefs/tar-rs/security/advisories/GHSA-3pv8-6f4r-ffg2): PAX parser desynchronization, affected through 0.4.45, fixed 0.4.46. Lindera's dictionary asset fetch really unpacks an external tar.gz during native compilation, with an expected MD5 check/cache path. Tar is also declared by the normal dictionary library; the DE/EN CLI branch does not call that builder. No user-upload archive or browser path is evidenced. Do not relabel all tar code as a test dependency.
- **Anyhow 1.0.102**, RUSTSEC-2026-0190, is real native error handling; the unsound operation specifically requires adding context then mutably downcasting the error. No Pagefind-owned `downcast_mut` call was found. A full transitive function proof was not performed; exploitability is unestablished, not disproved. **Crossbeam epoch 0.9.18**, RUSTSEC-2026-0204, is through Rayon, whose work is executed in indexing; the issue is invalid-pointer formatting, not every Rayon operation. No triggering pointer-formatting path is established. Stable compatible patches are available for both.
- **Tokio 1.50.0**, RUSTSEC-2026-0386, is selected with networking on Unix and runs the indexer. The flaw requires unsafe descriptor lifetime/validity conditions allowed by the safe `AsyncFd` constructors; it is not an ordinary use of `tokio::fs`. No Pagefind-owned `AsyncFd` call was found, and no complete transitive call proof was performed. Windows lacks that Unix API. Stable 1.51.6 or 1.53.3+ supplies the fix within the existing `1` range.
- **Rand 0.8.5/0.9.2**, RUSTSEC-2026-0097 / GHSA-cq8v-f236-94qc: needs both `log` and `thread_rng`, a reentrant RNG-using custom logger, and reseeding/logging conditions. The selected tree lacks Rand's `log` feature; 0.8.5 also lacks `thread_rng` as a separately named feature at that version. Do not infer a failure from generic use of randomness. Stable 0.8.6/0.9.3 are range-compatible fixes.

**zstd requires per-function treatment, not “all harmless” or “browser memory corruption”.** Native source trees select zstd 0.13.3 / zstd-safe 7.2.4 / zstd-sys 2.0.16+zstd.1.5.7 through Actix and extended dictionary compression. Features are `arrays,legacy,std,zdict_builder`; `experimental`, `seekable`, and `zstdmt` are absent. [Actix's decoder source](https://docs.rs/crate/actix-http/3.12.0/source/src/encoding/decoder.rs) does use `zstd::stream::write::Decoder`, the relevant wrapper for RUSTSEC-2026-0403. This is a plausible vulnerable API route **if a qualifying compressed body is decoded by a running server**; the recorded command does not run that server. This report does not establish an actual malicious input reaching it. Other routes remain assessed as follows:

| Advisory | Required behavior | Source-configuration assessment |
| --- | --- | --- |
| RUSTSEC-2026-0391 | Reuse an abandoned stream context with `with_context` | No such Pagefind-owned call found; transitive reuse proof incomplete. |
| 0395, 0399, 0402, 0404 | Experimental stable-input/dictionary/clone APIs; 0402 also multithreading | Required `experimental` feature absent (and `zstdmt` absent). |
| 0396, 0398, 0405 | Seekable API and malformed/uninitialized state or offsets | Required `seekable` feature absent. |
| 0397 | `OutBuffer::around_pos` with position beyond initialized vector length | Not feature-excluded; no triggering caller/input established. |
| 0400 | Mix one-shot dictionary calls and an unfinished stream on one context | Not feature-excluded; no triggering context reuse established. |
| 0401 | Untrusted dictionary-training sample sizes overflowing the sum | Dictionary-builder feature selected; untrusted sizes at this API not established. |
| 0403 | Malformed legacy frame, streaming write decoder, error then output flush | Wrapper exists in Actix; normal indexing does not start server. Still a meaningful conditional path. |
| 0406 | Change/reset dictionary or worker configuration on unfinished multithreaded context | Required `zstdmt`/multithreaded usage absent. |
| 0410 (`zstd-sys`) | wasm32 allocator failure | Native target is not wasm32; the **separate browser WASM has no zstd dependency**. Not applicable to that browser artifact graph. |

All of these remain recorded with full affected ranges/fixes in the ledger, including unsoundness notices. “Informational = unsound” describes memory-safety defects; it is not synonymous with an unmaintained notice or absence of security significance.

**Maintenance notices are a different unresolved obligation.** Bincode 2.0.1, core2 0.4.0, encoding 0.2.33, proc-macro-error 1.0.4, proc-macro-error2 2.0.1, unsafe-libyaml 0.2.11 and yaml-rust 0.4.5 are RustSec **unmaintained** records, not seven independently demonstrated exploits. They have no patched release in the advisory. Pagefind's extended native graph really selects the first six (proc macros run upstream during compilation), while `yaml-rust` enters even the minimal CLI through Twelf → serde_yaml 0.8.26. F12 still asks for maintenance evidence, so absence of an exploit does not automatically qualify them. Sätteri's separate bincode occurrence is test-only, as described above.

**Pagefind `0.0.0` is a source placeholder, not the product release.** GHSA-gprj-6m2f-j9hx affects Pagefind before 1.1.1. The release [versioning script][P-version] replaces the source placeholder with `GIT_VERSION`; the downloaded executable identifies itself as 1.5.2. The examined current client uses `import.meta.url` to find its base rather than the old clobberable `document.currentScript.src` path. Retain the scanner match as a version-identity correction, not an unresolved instance of the pre-1.1.1 bug. This is not a general exemption for placeholder-version packages.

### Upstream JavaScript tooling, including the critical finding

The exact source `package-lock.json` resolves:

- `@pagefind/js → ava → @vercel/nft → @mapbox/node-pre-gyp → tar@7.5.13`. All are dev ancestry. [GHSA-23hp-3jrh-7fpw](https://github.com/isaacs/node-tar/security/advisories/GHSA-23hp-3jrh-7fpw) is **CRITICAL**, affected `<7.5.19`, decompression/parse exhaustion when processing attacker-controlled archives. Five further tar advisories cover negative sizes, NUL paths, long-path recursion, PAX type confusion/desynchronization; the highest listed minimum patch is 7.5.21. No browser or product-build installation of this source-lock tar is evidenced. An upstream build installing the complete dev graph may expose installation/tooling paths, so “not bundled” does not prove the publisher's build uncompromised. ADR-0015 does not permit waiving a critical finding; establish the component/surface identity and supply-chain evidence instead.
- `ava → @vercel/nft → glob → minimatch → brace-expansion@5.0.5`: seven CPU/memory/recursion advisories. The fix covering all listed 5.x ranges is 5.0.12. Attacker-controlled glob/brace expressions are the trigger; no import into Pagefind's search, worker or highlight entry is present. This test/tooling graph is not installed by this website's Pagefind npm wrapper.
- `ava → supertap → js-yaml@3.14.2`: four YAML complexity advisories; 3.15.2 covers the listed 3.x ranges. They require parsing malicious YAML; not the Rust `yaml-rust` component and not client-side search parsing.
- Direct build dependency `esbuild@0.28.0`, plus `tsx → esbuild@0.27.7`: [GHSA-g7r4-m6w7-qqqr](https://github.com/evanw/esbuild/security/advisories/GHSA-g7r4-m6w7-qqqr) concerns the **Windows development server**, not esbuild-generated JS. The maintainer affected-version field mentions `0.27.3`; discovery gives `[0.27.3,0.28.1)`. Its fix is 0.28.1. The observed source build calls `esbuild.build`, not `serve`, and the actual website does not run this upstream build. Preserve the range discrepancy and both matched versions. A rebuild may use compatible `^0.28.0 → 0.28.1`; tsx's 0.27.x range needs its own compatible update rather than assuming that change reaches both copies.

### Astro compiler and Sätteri

**Anyhow 1.0.102 in the compiler lock is not selected by any inspected compiler release tree** (macOS, Linux GNU, Windows, WASI-thread).
