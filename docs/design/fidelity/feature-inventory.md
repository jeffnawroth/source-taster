# Source Taster feature inventory at cdbb3eb

This file lists every user-facing feature of the product UI at commit `cdbb3eb`, the state before the redesign. It is the acceptance checklist for the visual redesign: each row must still exist and work after the redesign. The inventory comes from the code, not from the prototypes.

## Method

- Scope: `apps/web`, `apps/extension`, `packages/ui/src` and `apps/website/src`. The PDF report content (rendered by the server) is included as one output row (SU-OU-12), because the redesign must not drop it.
- Line numbers are resolved from the files at `cdbb3eb` when this file is generated. A row points to the first relevant line, not to every line.
- Server problem keys reach the UI through the error alert (`m[errorKey]` in `check-workspace.tsx`). Rows for them point to that alert and to the key in `apps/server/src/http/problems.ts`.
- The Tests column is a heuristic. A test counts when it names the i18n key, contains the English or German message text (or a distinctive part of a template), uses the row's test ID or interaction pattern, or is named explicitly from its test title. The match can miss a test that asserts with a loose regex, and it can over-count short labels. Hits in `apps/server/test` are shown as "server only", because they do not exercise the UI. At most three test files are named per row.
- `apps/website/e2e/accessibility.spec.ts:35` runs axe (WCAG 2.2 AA) and a reflow check on every built route. Where it is the only test named for a page, the page is rendered and checked for accessibility, but its content is not asserted.
- Mode legend: All = every client; WS = web standalone; WH = web hosted; EXT = extension in both browsers; CH = Chromium extension; FF = Firefox extension; HOST = hosted mode (web hosted, or extension hosted); ACCT = account workspace (web hosted, or extension hosted with sign-in); SENS = account workspace with the sensitive account actions flag; SITE = website.
