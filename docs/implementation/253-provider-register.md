# #253 (Q09): provider, purpose, location and transfer register

Part of #70. This is the FA-UEB-13 register that [ADR-0012](../adr/0012-hosting-operations.md) requires, built from the accepted ADRs and from what the
code in this repository actually sends. It also lists where the current
privacy drafts disagree with that reality. It is an engineering input for the
legal review in #257, not legal advice and not a record of signed contracts.

## How to read this register

- **Status** says how firm a row is. `selected` means an accepted ADR names the
  provider. `candidate` means the provider is an ADR option, or the only
  option the ADR leaves open, and its contract is not signed. `implemented`
  means this repository contains the code that talks to it. `not selected`
  means the decision is still open.
- **Contract** is `none signed` for every row. No agent can sign, and every
  row stays an owner or lawyer gate until the DPA, the terms and the transfer
  mechanism have been read and accepted by a person. The register records
  what to ask for; it never claims a mechanism is in place.
- **Location** is what the ADR or the code states. A provider's corporate
  parent and support-access location can differ from the data location. FA-UEB-13 and ADR-0021 require both to be named before launch. Rows marked
  `confirm at signing` have not been checked against the provider's current
  published terms in this document.
- Private-service behaviour is cited by repository name and file path only
  (`jeffnawroth/source-taster-service`). Nothing from that repository is
  copied here.

## 3. AI extraction provider (ADR-0010)

AI extraction sends the text of References, and optionally the surrounding
running text, to the provider. That text is user-supplied content and can
include personal data (author names, and anything a user pastes). The code
adapter in `apps/server/src/ai/bedrock.ts` is the only adapter present and is
pinned to the `eu-central-1` Region, with a startup check that
`data_retention_mode` is `none` before any request.

Reference text must never be used for training and never stored by the
provider. The register row stays a candidate until the provider contract
states both in writing (FA-UEB-12).

## 7. Rows that depend on unsigned contracts

Rows 1 to 8, 10 and 12 to 15 depend on contracts or accounts that only the
owner can create. Until they exist, the register is a candidate list and the
privacy text must say `placeholder`, not name a provider as final.

## 8. What stays with a human

- Choose and contract every provider above (#116, #159 and #160 where they
  apply, #258 for the account steps).
- Read each provider's DPA and transfer mechanism and complete the `confirm at
signing` cells.
- Decide the AI provider (#159) and the e-invoicing supplier (#160).
- Lawyer review of the findings in section 6 (#257).
