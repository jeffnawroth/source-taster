# #110 — Versioned DPA in both clients

Implements the client/contract portion of [#110](https://github.com/jeffnawroth/source-taster/issues/110), under [#70](https://github.com/jeffnawroth/source-taster/issues/70) and ADR-0021. Public work started from a descendant of `7518bc9` and incorporates public integration `39f1409939cc950f9ce7874183a8d69567024ba9`.

## Delivered

- Dual-licensed transport schemas, OpenAPI and clients for authenticated packet inspection, operation-bound fresh proof, conclusion, recoverable operation status, retained downloads and subprocessor objections. Web cookies and opaque extension sessions use separate endpoints.
- Shared bundled DE/EN controls in the web app and native extension side panel, available to confirmed Accounts without checking paid entitlements. Every offered document/annex is shown before acceptance. The user supplies legal name, address and representative, attests business use/authority, requests a fresh email code and deliberately concludes.
- An existing Contracting party is read-only. A different party or corrected representative requires the reviewed support procedure; there is no Account/Owner migration or profile-edit shortcut.
- Stable operation IDs and authoritative status recovery. Only the opaque recovery ID is kept in session storage; party details and proof codes are not persisted by these controls. Changing interface language remounts the review rather than silently substituting another packet in a pending conclusion.
- Authenticated Blob downloads retain the service's exact accepted JSON bytes, including all document bodies, versions and the acceptance representation. Extension credentials never appear in download links. Receipt deep links open the agreement view after normal sign-in.
- Intended-change notices, delivery state, objection entry and unresolved processing holds are visible in the shared controls.

The private service owns packet publication, immutable legal records, atomic/idempotent conclusion, proof policy, mail delivery and processing restrictions. Public verification storage receives no Contracting party details or acceptance evidence. Both-program fixtures invoke trusted private operations through their existing source-only control channel; no test control endpoint is added to a production HTTP surface.

## Limits and review handoff

All agreement/annex content in automated fixtures is explicitly placeholder content for human legal review. No default production agreement is published by this change. The private service must be configured with the actual HTTPS Account UI URL before a packet can be offered.

This is implementation evidence, not legal sufficiency, browser qualification or deployment approval. Human review still owns the actual packet/roles/form/authority, language and translation, notification/delivery/effective-date terms, objection outcomes, retention/deletion schedule, blocked/deleted-account retrieval and contractual return procedure. Trusted packet/notice/review operations need the surrounding Operator/support procedures.

The supplier hold is conservative for the selected global configuration: affected Accounts cannot start new Structuring/Checks until reviewed prerequisites are resolved. There is no alternate supplier routing, silence-as-consent rule or automatic legal approval after SMTP success. Real supplier activation and operational queued/running/restore qualification remain review work; the automated fence test is narrower evidence.

The prepared private integration has not yet incorporated #101's Account Preferences endpoints. Its pre-existing synchronization warning can appear in hosted clients; DPA access still works in both languages. Reconcile the minimal Account-language initialization with that slice when integrating: supplier notices use the Account language; receipts retain the explicit agreement-language exception.

The native suite covers Chromium. Safari, native Firefox/ESR and other release-browser acceptance remain qualification work. The complete website/document/quality-gate suites were not rerun for this DPA slice.
