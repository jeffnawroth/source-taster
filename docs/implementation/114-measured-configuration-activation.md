Implementation handoff, 3 November 2026. This does not qualify or activate the service, close #114/#70, or change any release, hosted, provider, legal, security, Selected, Better Auth, minimatch or deployment gate. The five-hour retry job is outside this implementation and remains untouched.

## Ownership and protocol

Verification owns executable configuration, comparison rules, the private measurement dataset, replay observations, and eligibility. The private service owns the Operator command, fresh proof, immutable activation history, active pointer, operation recovery and audit. Its only public dependency for this work is the dual-licensed transport in `packages/contract-internal`; no AGPL verification, scoring or measurement implementation is imported into the private program. No Reference test set, recording, Check text or provider secret crosses the boundary.

`POST /internal/configuration/inspect` accepts `list` or `validate` with an opaque configuration ID. The existing Ed25519 assertion adapter binds issuer, audience, purpose `configuration-authority`, method, exact path, body hash, 30-second lifetime and a fresh UUID. Verification consumes UUIDs durably in its own schema. The reply contains safe review settings (provider/region/countries, model, source names, scoring parameters, search budgets), code/configuration/rules/evidence identities, refusal codes and inspection time. Private validation rejects malformed/inconsistent replies, a different configuration/evidence identity, or an inspection at least 30 seconds old or from the future.

`POST /internal/configuration/active` runs in the private service. It requires a separately signed request with the same purpose, its own exact path/body and durable replay protection. It returns only the immutable pointer identity, evidence digest, operation ID and increasing version. Verification persists a monotonic fence across web/worker restarts: lower versions and a different binding at an already observed version refuse. Service restore must catch up; it cannot silently downgrade a verifier's authority.

## Configuration and evidence

`SOURCE_TASTER_MEASURED_CONFIGURATIONS` names a deployment-owned JSON array (at most 100 entries). Each entry has `configuration` (the existing #94 configuration-file path), optional `extraction` (adapter entry-module path), private `root`, and `loadReport`. These are deployment inputs, never editable Operator JSON. Use immutable reviewed files and atomic deployment replacement. Adapter entry-module bytes are content-addressed, included in #94 measurement identity, and re-imported by that digest; provider identity alone cannot substitute for adapter code. Adapter dependencies must be included in the measured repository/locked deployment closure.

Inspection reuses `resolveConfiguration`, the ADR-0025 profile parser, `qualifiedAi`, `checkRelease`, and #117's load guard. It does not trust a log's `passed`, `qualifying` or target-status flags. Exact code, calibration, configuration bytes, selected parameters, source list, effective search settings, load scope/targets/clocks and reviewed-file digest remain mandatory. Process-wide worker concurrency and per-Check admission settings must match the deployed worker pool. Unsupported runtime routes refuse; this does not enable a preview or hosted deployment.

Scoring rules still truthfully report `uncalibrated` in this source tree. The existing loader still refuses hosted production execution, and release still exits 78 without real qualification. An Operator action cannot change these facts. Real calibration/measurement and the separately gated deployment must precede serving users; test results do not provide them.

Approval receipts are per configuration: `<root>/qualifications/<configuration SHA-256 hex>/provider-approval.json` and `<source>.json`. Provider approval additionally binds exact AI configuration, code, a retained contract artifact, EU-only processing/storage, zero retention, reviewer and expiry. Book (`openlibrary`, `googlebooks`), web (`url`, `internetarchive`) and Semantic Scholar activation require the applicable #138/#140/#136 source receipt. Missing, expired, malformed, withdrawn or mismatched evidence refuses.

Protected artifacts live at `<root>/qualification-artifacts/<SHA-256 hex>`. Each referenced artifact must exist and hash to its name. Source receipts require rights/service-use/storage approval, actual recorded acquisition provenance, the adapter version, and all applicable cases: ISBN plus bibliographic search for each book catalog; original page for URL; original page, availability and capture for Internet Archive; batch and search for Semantic Scholar. The approved-recordings artifact must declare `provenance: recorded` and link to its rights artifact. Synthetic provenance refuses.

A `source-taster-source-replay/1` artifact binds source/code/configuration/recordings and contains the actual published API outcomes plus reviewed expected identifier/title (and archive capture timestamp). The validator parses the full API result schema, rejects Status/failed-source outcomes, and checks actual Best-match identity/source/title or web observations against the reviewed expectation. Claimed successful counters without these artifacts cannot qualify a source. Acquisition, legal approval, private recording collection and real replay execution remain human qualification work; this implementation creates none of that evidence. The schemas in `source-qualification.ts` are the exact handoff format.

Only this configuration's matching measurement logs, frozen dataset, load report and applicable approval/artifact bytes enter its evidence digest. Unrelated configurations' logs or approvals do not invalidate its pointer. Evidence is bracketed around validation; replacement during inspection refuses. Every use revalidates eligibility and the exact stored digest, so withdrawal after inspection cannot become permission to dispatch or publish results.

## Checks and results

New hosted Checks snapshot the live active pointer and verified rules identity in the Check transaction. The request's selected extraction adapter and preview receipt share the same configuration context; a preview from another configuration cannot be adopted after a switch. Existing Checks retain their selection through edits, Re-checks, cancellation and restart. A database trigger prevents changing that snapshot.

Workers resolve the selected local configuration, apply its measured source/settings/profile, and validate the stored evidence at dispatch, source and publication boundaries alongside existing Owner/lifecycle authority. They never substitute the newly active configuration for old work. Missing local configuration, revocation, a stale authority fence, or a service partition refuses. Verdicts carry the measured-configuration ID; append-only result metadata retains that ID and the actual scoring rules version (or selected rules identity for a Status). Separate database protection prevents rewriting this metadata. Activation never rewrites earlier results, revisions or evidence.
