# WCAG 2.2 Level A and AA self-assessment (Q08, #256)

Part of #70. This is the first criterion-by-criterion assessment of every surface against the Web Content Accessibility Guidelines (WCAG) 2.2 at Levels A and AA, as `docs/technical-concept.md#q08` requires before a launch candidate. It is a self-assessment by the implementation agent from the automated and scripted checks listed under Evidence and from code review. It is not an independent audit and it makes no conformance claim. Native screen-reader reviews are not part of it: rows that depend on them say so and point to #217 (VoiceOver and other assistive technology on the web surfaces) or #105 (the PDF report).

## Surfaces

- **Web app, standalone (WS)**: `apps/web` and `packages/ui`, guest use of the program served by `apps/server`. No sign-in.
- **Web app, hosted (WH)**: the same app with the hosted-only screens: sign-in with a one-time code, history, quota, invoices, the processing agreement (DPA), rights, and the maintenance banner. The browser passes ran against the standalone stack, so the rows for hosted-only screens rest on CI axe and code review.
- **Extension side panel (EX)**: `apps/extension`, `panel.html`. It mounts the same `packages/ui` components, so the web passes cover its markup and the extension suites (E5) cover its states.
- **Website (SITE)**: `apps/website`, the static Astro site with the documentation, FAQ, legal pages and the accessibility statement.
- **PDF report (PDF)**: the tagged report from `apps/server/src/reports`. Success criteria are read through W3C's note on applying WCAG 2 to non-web information and communications technology (WCAG2ICT): criteria that depend on Web pages, repeated blocks or a user agent are N/A.
- **Email (MAIL)**: the transactional messages, an HTML and plain-text pair per message, built in the private repository. Only aggregate results are given here.
- **Private service pages (SVC)**: the Account, commerce and Operator pages of the private repository. Only aggregate results are given here; details are in jeffnawroth/source-taster-service#62.

Method codes in the rows: Axe (axe-core in a browser or in CI), Keyboard (scripted Tab traversal), Probe (other scripted browser checks), CI (an existing CI suite), CR (code review), Computed (a contrast calculation), Inspect (PDF structure inspection).

## Notes on the method

- The browser passes use `bypassCSP` only to inject the text-spacing stylesheet; no other setting differs from a normal run.
- The command palette is scanned separately. Axe reports `scrollable-region-focusable` on its list at 320x256: the list is operated by arrow keys from the search field and the keyboard-scroll probe reaches the last item in view, so the finding is recorded as a false positive. Axe also reports `label-content-name-mismatch` for the disabled "check" command, because its reason text is exposed as the description, not the label; the label is contained in the name, so 2.5.3 is judged met.
- The web `e2e` specs use four axe tags and leave out `wcag21a`; the extension and website suites use all five. The scans in E1 use all five and found one genuine failure of 2.5.3 that the web suites could not (see Findings).
- Smooth scrolling made immediate rectangle measurements unreliable; the keyboard pass waits for scrolling to settle after each Tab.
