## Actual large-export behavior

- Each program independently streams its own retained data directly to the verified recipient. Private accounting remains an authorized Operator export. Verification content and previews never reach ordinary Operator APIs or the private backend. Operator responses never expose recipient retrieval credentials.
- Content-free PostgreSQL membership snapshots freeze selected identifiers and source versions atomically. Indexed one-row seeks traverse Checks, metadata, references, revisions, results, events, reports and the private Account/billing/legal collections. Later inserts are excluded from an existing snapshot; changed/deleted selected records invalidate it. The UI can explicitly select a new snapshot under the same still-current recipient authority.
- The default decoded wire part is **64 KiB**, configurable safely from **512 B to 256 KiB**. Sequence numbers, per-part SHA-256, a hash chain, signed cursors and a final manifest identify request, program, snapshot, time, counts, total bytes and whole-document SHA-256. Concatenating decoded part bytes in sequence recovers the complete machine-readable JSON. A single large record spans parts; it is never dropped because it cannot fit one part.
- PDF/UBL reads use **12 KiB SQL bytea slices**, preserving exact original bytes and hashes without a whole-invoice buffer. Accounting uses durable SQL-selected membership instead of a JavaScript invoice-ID array. It retains chronological invoice order, archived historical evidence, incomplete-archive status and exact BigInt country/currency totals across all parts. Selected periods have valid UTC half-open dates without the old 366-day refusal. Refund/credit-note business-object scope remains the source's explicitly deferred workflow; no financial evidence is invented.
- Working memory consists of the current retained traversal path/decrypted storage values, fixed codec/serialization/transport buffers, bounded browser files and country/currency accumulators. The existing accepted document/storage/codec limits still apply. Account-wide content, relation arrays and invoice binaries are not assembled before partitioning. There is no export-wide Check/invoice/metadata count or aggregate JSON/binary refusal.
- The browser saves one bounded file per explicit press, up to **8 MiB** with normal settings, and exposes the final manifest separately. This avoids automatic multiple-download dependence. Tentative frame/cursor state is committed only when its bounded file is saved. Repeating the same button resumes from the last saved frame; an explicit new-snapshot control handles changed retained data. The small-capacity browser fixtures exercise the same path with aligned **1 KiB** frame/file limits; the final published-pin run uses the ordinary 8 MiB build. DE/EN instructions, keyboard flow and axe checks pass.
- Resume cursors bind the credential, request, program and snapshot. Restart reconstructs unchanged snapshots by replaying and checking the prefix with bounded reads, without retaining plaintext checkpoints. Current recipient/Operator authority, revocation/deletion/restore epochs, source versions and original retention deadlines are checked before frames and completion. Interrupted streams have no successful manifest or usable completion receipt. A final opaque completion proof is returned only to the recipient; the service sees only content-free authority/status coordination. Recipient receipts remain idempotent.

The verified-mailbox/fresh-session or independently reviewed exceptional route, original **24-hour maximum** retrieval grant and calendar-month case deadline remain. A Check/report's shorter deadline still wins. Blocked/deleted Account retrieval never restores normal access, transfers Guest content or resurrects erased data. Only snapshot coordination metadata is persisted, for at most the grant window; no temporary export payload archive is created. Mail, audits, logs and support responses retain the existing content/credential exclusions.
