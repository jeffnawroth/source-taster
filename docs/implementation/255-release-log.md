# #255 (Q11): release log and Operator preparation review

Part of #70. This is the release log that Q11 in the [technical concept](../technical-concept.md#q11) requires: one place that records the state of every qualification packet Q01 to Q11, the six §12.1 launch-preparation requirements, every §19 trigger, the versions in use and every pending gate. Each pending gate links to an open issue, so closing a gate means closing its issue and updating the row here.

It is a record, not an approval. No row below says that a gate passed unless a cited document says so, and nothing here activates, qualifies or deploys anything. No provider, lawyer or person was contacted for it. Status is as of 2026-11-20, `main` at `1d6bbb27`.

## How to keep it current

1. When a gate closes, set its row to the new state, name the evidence file or issue comment, and date it.
2. A row never moves to "passed" on a local run alone. Hosted CI, a real device or a signed human review has to be cited (see the reading rules in the [launch integration log](70-launch-integration-log.md)).
3. A should requirement that is not met is recorded under "Should deviations" with a reason, not dropped.
4. A new pending gate gets an issue first, then a row.
