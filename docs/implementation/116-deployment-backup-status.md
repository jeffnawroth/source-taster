## Encrypted export operation

After provisioning, supply a mode-0600 file through `OPS_CONFIG` using `deploy/backup.example.json`, this program's restricted `DATABASE_URL`, and dedicated `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`. The DB role must own only its program schemas, never be a superuser/role creator/bypass-RLS role. Keep the export writer unable to delete objects, change retention, or administer the bucket. It holds only an RSA public key (minimum 3072 bits); the private key is offline, with password-manager/deputy recovery and paper custody. Do not put it in the app, S3, DB, logs, command arguments or backup config.

```sh
node apps/server/ops/backup.mjs export
```

The command uses real `pg_dump` 18 with a bounded five-minute process and 1 GiB plaintext limit. libpq credentials travel in child environment fields, never argv. It selects only `verification`/`verification_boss`; the service independently selects `service`/`service_boss`. It encrypts while streaming with random AES-256-GCM and an RSA-OAEP-SHA256 wrapped data key, authenticating format/program/schema/time/schema-version metadata. Plaintext is never spooled during export. Private temporary directories contain bounded ciphertext and receipts and are cleaned on completion/failure. Crash-killed temporary directories require the host's private ephemeral-directory cleanup; do not snapshot them.

`--no-unlogged-table-data` excludes daily transient keys. Public abuse counters/origin pins, ephemeral export members/snapshots and worker pulses are excluded. The service additionally excludes purpose-limited abuse accounting, session/challenge/fresh-proof material, Operator grants and delivery cursors/snapshots. Retained Account/Owner blocks, tombstones, legitimate Quota grants, immutable legal records, History and their original deadlines remain. The private service's existing external authority epoch invalidates retained DSR grant verifiers; no raw grant is backed up. Losing counters never resets admission allowance: the existing restore epoch/window fence drains up to 24 hours.

Scaleway Paris S3 is the only production endpoint. Each dedicated program bucket must have versioning, Object Lock enabled, COMPLIANCE retention and the reviewed lifecycle. Uploads specify 312 hours (13 days) of immutable retention; lifecycle expiration is 13 days with noncurrent expiration 1 day, leaving the bounded cleanup tail inside the approved 14-day envelope **subject to actual provider qualification**. Object Lock is not a deletion guarantee; human Q06/Q09 must prove physical/policy backup-tail behavior, including versions/delete markers and interrupted-upload orphans. Missing or incompatible bucket policy refuses before dump/upload. HEAD readback verifies version, mode and retention; GET readback verifies SHA256 of every encrypted byte. Only after that does a separately locked/read-back `.complete` record publish completion. An interrupted upload, missing completion part, wrong version, retention downgrade, tamper, decryption failure or schema mismatch refuses with a content-free failure receipt. No plaintext or retention downgrade is possible through an alternate flag.

A complete receipt identifies backup key/version/hash/time/retention and completion-object version. Retain it separately in restricted operations evidence. It contains no Reference, email, Owner ID, IP, credential or daily key. Key-custody/rotation/recovery receipts are separate from backup receipts. Key rotation needs an offline recovery test of old and new public-key generations before retiring the old private key after its last retained export expires.

`ops/scheduler.mjs` is a separate opt-in process at UTC 00/06/12/18. It never overlaps exports, and emits failures; no scheduler was installed or activated here. `deploy/backup.cron` is an alternative, never an additional scheduler. Provision independent missing-success/dead-man monitoring for the six-hour receipt before enabling either. Never run an actual alert while validating locally.
